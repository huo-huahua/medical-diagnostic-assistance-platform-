# 问答路径对比 · 设计与使用

> 同一个问题，三条路径同时作答，并把**差异**摊开给你看。
> 这一页要回答的不是「模型答得好不好」，而是：
> **有了检索和没有检索，答案到底差在哪里？这份差额值多少钱？**

对应优化项：[`OPTIMIZATION_BACKLOG.md`](OPTIMIZATION_BACKLOG.md) 第 13、14 条（知识库与切块）与新增的对比能力。
怎么把这里的外部路径接到**真实大模型**（8 家服务商、探活、错误分类、密钥管理），见 [`LLM_INTEGRATION.md`](LLM_INTEGRATION.md)。

---

## 一、为什么要做这件事

本平台默认的问答是**纯本地**的：`sentence-transformers` 嵌入 + FAISS 检索 + 模板作答，一次外部 API 都不调用。这是一个刻意的成本选择，但"因为省钱所以用本地"只是结论的一半——**另一半是：本地路径到底牺牲了什么？**

大语言模型有一个麻烦的性质：**它无论对错都答得很流畅**。所以"看起来更好"完全不能作为判断依据。把三条路径并排放在同一张表里，差异就变成可测量的：

| 你想验证的直觉 | 表里对应的列 |
|---|---|
| 「模型直答会不会胡说？」 | `引用数`、`词面重合度`、`绝对化措辞` |
| 「加了检索是不是更靠谱？」 | `引用数`、`词面重合度` 对比 `外部直答` |
| 「这份'更靠谱'值多少钱？」 | `外部调用`、`Token`、`费用(¥)`、`耗时` |
| 「同一个问题重复问会不会重复付费？」 | `缓存命中` |

## 二、三条路径

| 键 | 名称 | 用检索 | 外部调用 | 说明 |
|---|---|---|---|---|
| `local_rag` | 本地检索增强 | ✅ | ❌ | 检索本地知识库，直接以原文片段组织答案并标注出处。全程离线，成本为零。 |
| `llm_direct` | 外部模型直答（无检索） | ❌ | ✅ | 把问题直接交给外部大模型，**不提供任何参考资料**。这是观察"幻觉"风险的基线路径。 |
| `llm_rag` | 外部模型 + 检索增强 | ✅ | ✅ | 先本地检索，再把原文片段作为上下文交给外部模型组织语言。兼顾出处可核查性与表达流畅度，代价是每次调用产生费用。 |

> `llm_direct` 永远不带检索。它是**对照组**——一旦给它加上上下文，这个对比就失去意义了。

## 三、怎么用

### 3.1 在界面上

侧栏 → **问答对比**（`/qa-compare`）。

1. 在右侧选择病种（检索范围）；
2. 输入问题，点「开始对比」；
3. 表格按**行 = 指标、列 = 路径**铺开，同一行对所有路径施加同一种度量；
4. 下方「怎么读这张表」面板列明每个指标的**能说明什么、不能说明什么**；
5. 「历史对比」列出你跑过的每一次对比，可展开回看或删除。

想在表格里看到外部两列的真实内容，先看页面顶部那块 **「外部模型连接」** 面板（状态、服务商目录、探活自检），
或直接把 `LLM_PROVIDER` 设成 `mock` 用离线演示通道。详见 [`LLM_INTEGRATION.md`](LLM_INTEGRATION.md)。

### 3.2 走接口

```bash
TOKEN=$(curl -s --noproxy '*' -X POST http://127.0.0.1:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"demo@bcdx.dev","password":"demo12345"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['data']['access_token'])")

curl -s --noproxy '*' -X POST http://127.0.0.1:8000/api/v1/rag/compare \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"question":"BI-RADS 分级是什么意思？","disease":"breast","persist":true}' \
  | python -m json.tool
```

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/rag/compare` | 跑对比。`paths` 可只传子集，如 `["local_rag"]`；`models` 可传多个模型名 |
| `GET` | `/api/v1/rag/comparisons` | 最近 30 次对比（当前用户） |
| `GET` | `/api/v1/rag/comparisons/{id}` | 单次对比全文，含三条路径的完整答案 |
| `DELETE` | `/api/v1/rag/comparisons/{id}` | 删除一次对比 |

访问他人对比返回 **403**，不区分"不存在"与"不属于你"。

### 3.3 一次比较多个模型

`models` 传入多个模型名时，每条外部路径会为**每个模型各生成一列**：

```bash
curl -s --noproxy '*' -X POST http://127.0.0.1:8000/api/v1/rag/compare \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"question":"BI-RADS 分级是什么意思？","disease":"breast",
       "models":["model-a","model-b"],"persist":true}' \
  | python -m json.tool | grep '"key"'
```

返回的路径键是 `local_rag`、`llm_direct@model-a`、`llm_direct@model-b`、`llm_rag@model-a`、`llm_rag@model-b` —— **5 列**。

四个刻意的约定：

| 约定 | 原因 |
|---|---|
| 模型名先清洗：去首尾空格、去重、只允许 `[A-Za-z0-9._:\-/]` 且 ≤ 64 字符 | 防止畸形名字被拼进缓存键与日志 |
| 上限 `LLM_MAX_COMPARE_MODELS`（默认 **3**） | 每个模型要两次付费调用，不封顶的列表就是不封顶的账单 |
| 接口**回显清洗后的列表** | 被丢掉的模型你能立刻发现，而不是对着少一列的表发呆 |
| 不传 `models` 时响应与原来**完全一致**（三列） | 老调用方不受影响 |

> **前端行为**：页面上「使用的模型」输入框填多个名字（逗号或空格分隔）即可。若当前是**演示通道**，
> 「同时运行两条外部模型路径」开关会**默认打开**（因为它不花钱）；接入真实模型时该开关保持默认关闭，
> 需要你显式同意才会计费。

## 四、实测结果（本机默认配置）

本机 `.env` 里 `LLM_ENABLED=false`、未配置 API Key，也就是**默认的零成本状态**。问题：`BI-RADS 分级是什么意思？`

### 4.1 未配置外部模型

| 指标 | 本地检索增强 | 外部直答 | 外部 + RAG |
|---|---|---|---|
| 状态 | `ok` | `skipped` | `skipped` |
| 答案字数 | 682 | — | — |
| 引用条数 | 2 | — | — |
| 词面重合度 | 1.00 | — | — |
| 绝对化措辞 | 无 | — | — |
| 外部调用 | 否 | — | — |
| 费用（¥） | 0 | — | — |
| 耗时（ms） | 39 | — | — |

检索侧：`top_score = 0.8153`，命中 5 个片段，合并为 2 个引用段落。
第一条引用 `乳腺癌知识库 > BI-RADS 分级含义（合并 4 段）` 是把同一小节被切开后的 4 个片段**重新拼回一段**（见 [`KNOWLEDGE_BASE.md`](KNOWLEDGE_BASE.md) 的"小切片检索、大段落引用"）。

`summary`：

```json
{
  "external_calls": 0, "cache_hits": 0,
  "prompt_tokens": 0, "completion_tokens": 0,
  "cost_cny": 0.0,
  "grounded_paths": ["local_rag"], "ungrounded_paths": [],
  "llm_available": false
}
```

**关键点：`skipped` 不等于 `failed`。** 两条外部路径返回 `skipped` 只是说明这个部署没有开启付费调用，对比功能本身完全正常。`llm_available: false` 与 `cost_cny: 0` 是同一件事的两种表达。

> 上表的空单元格是**如实留空**，不是省略。没有配置外部模型，就没有这三列的真实数据；任何"典型输出"都只能算举例，不能算实测。

### 4.2 配置了外部模型之后会发生什么

把 `.env` 改成：

```ini
LLM_ENABLED=true
LLM_API_KEY=sk-你的真实密钥
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

则：

- `llm_direct` 返回 model 在**没有任何上下文**下生成的回答，`引用条数 = 0`，`词面重合度` 由「答案词汇有多少出现在检索语料里」算出；
- `llm_rag` 返回注入了检索片段的回答，`引用条数` 与本地路径一致；
- 两者都会记录 `prompt_tokens` / `completion_tokens` / `费用(¥)`；
- 前端「调用状况」与总览页的 LLM 调用次数开始增长。

### 4.3 演示通道下的实测结果（不需要密钥，可复现）

没有密钥也想看到三列/五列都有内容？把 `LLM_PROVIDER` 设成 `mock`。它不出网、不花钱，
但走的是**同一套代码路径**——OpenAI SDK 的序列化、重试、错误映射、token 记账、缓存全部真实执行。

本机实测（`LLM_PROVIDER=mock`、`LLM_ENABLED=true`，问题 `BI-RADS 分级是什么意思？`，模型 `model-x` / `model-y`）：

| 指标 | 本地检索增强 | 外部直答·model-x | 外部 + RAG·model-x | 外部直答·model-y | 外部 + RAG·model-y |
|---|---|---|---|---|---|
| 状态 | `ok` | `ok` | `ok` | `ok` | `ok` |
| 引用条数 | 2 | **0** | 2 | **0** | 2 |
| 词面重合度 | 1.000 | **0.036** | **0.517** | 0.036 | 0.517 |
| 答案字数 | 682 | 277 | 774 | 277 | 774 |
| Token（prompt+completion） | — | 208+258 | 752+660 | 208+258 | 752+660 |
| 费用（¥） | 0 | 0 | 0 | 0 | 0 |
| 耗时（ms） | 14 | 18 | 18 | 19 | 17 |

**这一次冷启动**：`external_calls = 4`、`cache_hits = 0`、合计 `1920 + 1836` token。
**紧接着重跑同一个请求**：`external_calls = 0`、`cache_hits = 4`、token 归零 —— 缓存生效的实证。

三个值得看的数字：

1. **词面重合度 0.036 → 0.517**。直答路径没有任何参考资料，措辞与本地语料基本无关；检索增强路径的答案
   回显了片段里的关键词。演示模型是本地代码生成的，但它**刻意复刻了真实效应的方向**——
   否则表里会出现两条一模一样的行，这个对比就白做了。
2. **引用条数 0 → 2**，直答路径被正确标记为 `ungrounded_paths`（无出处作答）。
3. **费用全是 ¥0**，因为演示通道不连接任何付费服务。若换成真实模型，同样这 4 次调用按 DeepSeek
   定价约为 `1.920 × 0.002 + 1.836 × 0.008 ≈ ¥0.019`——**一次对比不到两分钱，而且重跑不再收费**。

> 模型名清洗也在这里可验证：传 `["deepseek-chat","gpt-4o-mini","  deepseek-chat  ","bad name!"]`
> 会回显 `["deepseek-chat","gpt-4o-mini"]`（去空格、去重、丢弃非法字符）；传 4 个合法名字时
> 只保留前 `LLM_MAX_COMPARE_MODELS`（默认 3）个。

**想复现"调用失败"的样子**：演示通道支持故障注入。设 `LLM_MOCK_FAULT=quota`（或
`invalid_key` / `endpoint_not_found` / `rate_limited` / `timeout` …）后重启后端，
每次演示调用都会按该错误类型失败，「测试连接」会直接告诉你属于哪一类。详见 [`LLM_INTEGRATION.md`](LLM_INTEGRATION.md)。

### 4.4 真实密钥下的实测结果（DeepSeek · deepseek-chat）

上面两节都是"离线可复现"的。这一节是**真钱真网络**跑出来的一次，用来回答"真实模型会不会也是这个方向"。

实测条件：`LLM_PROVIDER=deepseek`、`LLM_MODEL=deepseek-chat`、`LLM_ENABLED=true`，
问题 `乳腺癌筛查应该多久做一次？`，病种 `breast`，单次冷启动（`cache_hits = 0`）。

| 指标 | 本地检索增强 | 外部直答（无检索） | 外部 + 检索增强 |
|---|---|---|---|
| 状态 | `ok` | `ok` | `ok` |
| 引用条数 | 4 | **0** | 4 |
| 词面重合度 | 1.000 | **0.165** | **0.685** |
| 答案字数 | 671 | 861 | 412 |
| Token（prompt+completion） | — | 139+492 | 541+262 |
| 费用（¥） | **0** | 0.004214 | 0.003178 |
| 耗时（ms） | **40** | 3057 | 1700 |

这一次合计：`external_calls = 2`、`prompt 680 + completion 754` token、**¥0.0074（不到一分钱）**。

四个值得看的地方：

1. **演示通道给出的方向和真实模型一致**：直答 0.165、检索增强 0.685。差的是一个数量级，不是噪声。
2. **最长的答案不是最可用的**。直答 861 字、分年龄段讲得很细，**但 0 条引用**；它给的是欧美口径
   （40–49 岁个体化、50–74 岁每 1–2 年），与本地知识库"40 岁起每 1–2 年"并不一致。
   **它不一定错，只是你无法核对它依据的是哪份指南**——这就是"无出处"的真实代价。
3. **外部 + 检索增强最短（412 字）却最贴合本地资料**，并且会明说"资料中未提及"，
   而不是把没检索到的细节补全。这是三种里最适合放在医疗场景的一种。
4. **本地路径 40 ms、¥0**，是唯一可以无限次跑的；两条外部路径的耗时由网络和服务商决定，
   1700 / 3057 ms 之间那一秒多的差异**不可当作性能结论**。

> 这次对比的完整输出（含三份回答原文与 4 条出处）已归档为
> [`samples/qa-comparison-live.json`](samples/qa-comparison-live.json)，
> 可用 `_tools/render_compare_report.py` 渲染成
> [`samples/qa-comparison-live.html`](samples/qa-comparison-live.html)——
> 一份可以直接打开、打印或放进汇报材料的单页报告。

**顺带暴露的一个显示瑕疵**：本地路径那份答案里有一行重复了
（"…建议提前至 30 岁起开始筛查，并联合每年一次乳腺 MRI…"后面又跟了半句同样的内容）。
原因是该片段标注为「合并 2 段」，两段的重叠部分在**展示时没有去重**。
它不影响检索与判定，只是本地答案读起来有重复。**尚未修复**。

## 五、怎么读这张表（度量口径）

这一节是文档里最重要的部分。**表里的每个指标都有它的局限，把局限写清楚比把数字做大更重要。**

### `引用条数`

- **能说明**：答案是否有可核查的出处。`0` 意味着每条结论都无从验证。
- **不能说明**：引用是否正确。它只数条数；正文与出处的对应关系需要人去看 `[^c1]` 标号。

### `词面重合度`（`lexical_overlap`）

定义：答案中长度 ≥ 2 的 token，有多大比例在检索到的语料里出现过。分词方式是**中文字符二元组 + 英文/数字词**。

- **能说明**：答案的**措辞**是否来自检索文本。抄自语料的答案自然复用其用词。
- **不能说明**：
  - **高 ≠ 正确** —— 只证明这些词在语料里出现过；
  - **低 ≠ 错误** —— 中文医学术语高度集中，即使是纯靠参数记忆生成的答案，也会与知识库有一定重合。
- 它可靠地反映的是**方向**：有语料 vs 无语料的答案，措辞来源确实不同。
- 本地路径固定记作 `1.0`（答案本身就是语料原文），这是定义使然，不是"表现最好"。

### `绝对化措辞`（`risk_phrases`）

对「一定 / 保证 / 绝对 / 100% / 无需就医 / 肯定 …」做关键词匹配（匹配前做 NFKC 归一化，所以全角 `１００％` 也会被识别）。

- **能说明**：出现了这些词，值得人工再读一遍。
- **不能说明**：**它是一个浅层关键词筛选，不是安全保证。** 没有命中不代表回答安全，命中也不代表回答错误。不要把它当成合规检查。

### `费用(¥)`

按 `LLM_PRICE_PROMPT_PER_1K` / `LLM_PRICE_COMPLETION_PER_1K` 与本次 token 数**估算**的展示值。

- 默认 `0.002` / `0.008`，按 DeepSeek 定价量级设置，**请在换模型时同步修改**；
- 它是估算，不是账单。真实扣费以服务商结算为准。

### `耗时(ms)`

- 索引构建（一次性的嵌入计算，冷启动可达数十秒）在计时**之前**完成，不计入任何一条路径的耗时；
- 本地路径约 **30–60 ms**；外部路径包含网络往返，通常数百毫秒到数秒。

### `状态`

| 值 | 含义 |
|---|---|
| `ok` | 路径正常完成 |
| `skipped` | **按设计没有执行**，不是错误。三种情形：未配置外部模型、`QA_COMPARE_ALLOW_LLM=false`、本地检索已判定问题超出范围 |
| `failed` | 本应执行但没拿到结果（网络失败、密钥无效） |

### 问候语是一种特殊情况

输入「你好」这类纯问候语时，本地路径返回的是引导文案，**不带任何引用**。注意区分两件事：

- **没有引用** —— 因为答复根本没用到知识库（问候语本来就不需要出处）；
- **无出处作答**（`ungrounded_paths`）—— 指**给出了结论却没有可核查的来源**，那才是风险。

把前者算作后者，等于把最安全的回答标成最高风险，所以问候语被排除在 `ungrounded_paths` 之外。

同理，`llm_rag` 路径在问候语场景下不会把问题转交外部模型：注入的检索片段与输入毫无关系，调用它没有意义。

## 六、成本控制：为什么它不会失控

这一节对应项目的硬约束——**外部 API 调用次数必须尽可能少**。

### 6.1 四道闸门（沿用 LLM 网关）

| 层 | 机制 | 效果 |
|---|---|---|
| 硬开关 | `LLM_ENABLED=false` 或密钥缺失 | 请求根本不出进程，直接返回 `skipped` |
| 精确缓存 | 归一化后的 prompt 做 SHA-256 | 同一个问题**只付一次钱**，标点/空格/大小写/全角差异都算同一个 |
| 语义缓存 | 嵌入余弦相似度 ≥ 0.94，**且限定在同一调用点内** | 换个说法问的同一问题，也命中缓存 |
| 模型入缓存身份 | 缓存 key 为 `purpose@model` | 换模型一定会重新调用；否则对比两个模型时第二个直接命中第一个的缓存，**根本没被调用**，表格里两列一模一样 |

> 第 3 条"限定在同一调用点内"不是细节。`rag` 与 `qa_direct` 的 cache payload 都从**同一个问题**生成，
> 向量余弦相似度接近 1.0。不加限定的话，「外部直答」会被喂一份**检索增强的答案**——而"有检索和没检索的差别"
> 恰恰是这一页存在的唯一理由。这条有专门的测试钉着（`test_the_semantic_cache_does_not_cross_call_sites`）。

### 6.2 缓存按"问题 + 调用点 + 模型"计价，而不含检索片段

外部路径的缓存键**只包含问题本身**（`direct::<问题>`），不包含注入的上下文。含义是：

- 「同一问题 + 不同的检索片段」视为同一次调用，不会因为重新检索而重复付费；
- 反复跑同一个问题做对比，第二次起 `外部调用 = 0`、`缓存命中 = 1`、`费用 = 0`；
- 但**换一个模型再跑，是会重新调用的**——这正是多模型对比能成立的前提。

### 6.3 `llm_rag` 会主动跳过

两种情况下**不调用**外部模型：

1. **本地检索已判定问题超出病种范围** —— 把一个跨病种问题交给外部模型，等于把自己刚建立的病种隔离拆掉了；
2. **检索片段总长不足 `LLM_MIN_CHARS_FOR_CALL`（默认 150 字）** —— 上下文太短，调用它不划算。

### 6.4 一次付费调用的成本量级

设回答消耗 800 prompt token + 400 completion token：

```
800 / 1000 × 0.002  +  400 / 1000 × 0.008
= 0.0016 + 0.0032
= ¥0.0048        # 约半分钱
```

对比之下，本地路径是 **¥0**。这个对比就是本页存在的意义：**"更流畅的表述"每次约半分钱，而且重复问不再收费。**

### 6.5 其他约束

- 接口按 `RATE_LIMIT_LLM`（默认 `12/minute`，逐用户）限流；
- 问题长度上限 `QA_COMPARE_MAX_QUESTION_CHARS`（默认 300 字），超长会被截断并在响应里置 `truncated: true`；
- 每一次对比都会落库（`qa_comparisons` 表），**成本是可持续审计的**，不是一个跑完就消失的数字。

## 八、设计上的一个关键决定：检索只做一次

三条路径共享**同一次**检索结果。这是刻意的：

- 如果每条路径各自检索，差异就同时来自"检索结果不同"和"组织方式不同"，**两个变量混在一起，结论无法归因**；
- 共享检索后，**表里所有的差异都只能来自组织方式**——这正是要比较的东西；
- 副作用是成本：一次对比只付一次检索的算力，尽管表里出现了三列。

实现上，`retrieve()` 先建好索引再开始计时，返回的 `Retrieval` 对象被三条路径共用；`llm_direct` 也会拿到它，但**只用来算 `词面重合度`，不会注入 prompt**。
